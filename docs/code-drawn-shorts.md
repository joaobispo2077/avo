# Code-drawn alpha in Shorts

HyperFrames remains the default. Advanced code-drawn Shorts reuse a registered, canonical drawing alpha over original picture and independent audio. They do not compile a HyperFrames project or regenerate graphics during the Shorts proof.

A new request may select `motionEngine: "code-drawn"` in `defaults` or in one candidate. The selected item records `codeDrawn` with the canonical `instanceId`, `manifestRef`, original `inputLockRef`, and `generatedAssetRef` containing its asset ID, sealed record hash and receipt locator. Manifest paths are relative to the footage root. Receipt and original-lock references identify the actual registered files. Candidate engine overrides take precedence over defaults. An explicit contrary binding is invalid.

Native resolution consults the shared global, provider/channel and project preference resolver, then pins each new item. Explicit request choices take precedence. Approved older plans without a motion field retain their historical HyperFrames route. Changing a saved preference does not reinterpret an existing plan.

The initial code-drawn path requires the source-fidelity 10-bit output profile, one contiguous original-source segment at speed 1, and the same selected canonical content. The admitted alpha must cover the entire canvas with the exact output size, rational frame rate and duration, and must be silent with straight alpha. A resized preview needs a newly authored and bound alpha for that size. Non-fidelity output, split layout, HyperFrames widgets/callouts, punch-ins and visual inserts fail before preparation. Remotion remains selectable as a preference but has no native Shorts renderer.

All visible drawing content must be authored in its inspectable source. Nonempty planned captions additionally require the drawing manifest to declare `extensions.shortsCaptionPlanHash`: SHA-256 of the exact planned `captions` array serialized as UTF-8 canonical JSON, with sorted object keys, preserved Unicode, no whitespace separators and no non-finite numbers. Use the resolved item caption array without changing word IDs, times or text. Author that caption plan into the drawing, refresh the declared source file fingerprints and manifest seal, freeze a new original input lock, regenerate/register the alpha, update the request binding and resolve the new plan revision. An absent or mismatched declaration blocks the proof. Empty captions need no declaration. The declaration binds authored intent; human visual and caption review is still required.

Before media work, Shorts checks the current canonical heads, source interval, placement, local source closure and forbidden-output inventory. It observes the actual drawing runtime and admits the exact receipt. It repeats fresh observation and admission after encoding before publishing the proof report. Reusing an existing proof also requires current runtime admission. The report records the actual generated receipt, original input lock and generator identity, alongside original-source and audio identities. Unused HyperFrames template files do not determine a code-drawn proof's freshness.

This extends the existing immutable proof, review and delivery workflow. A technically valid alpha or proof does not grant a human watch approval, rights approval or delivery approval.
